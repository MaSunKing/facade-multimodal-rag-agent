# 问题相关多模态上下文

## 输入与输出

输入为当前问题、Planner目标词、各工具候选Evidence及来源位置。输出为评分/去重后的候选、关系保护信息、目标覆盖提示，以及供生成阶段压缩的载荷。

```text
完整解析 → 问题检索 → 跨来源排序/去重 → 关系保护
 → 动态候选预算 → 实际tokenizer提示预算 → 文本 + 有限图片
```

## 两种预算不能混淆

- 附件检索采用不加载模型的估计Token；默认候选预算5k，可配置。
- 最终提示包含问题、规则、历史、元数据及Evidence，用模型tokenizer实际计数。
- `choose_context_budget`根据任务、来源数量和视觉需求分配，不按文件字节数判断重要性。
- 图片有数量和像素预算，输出也有限制。配置上限不是模型理论上下文长度。

## 保护与压缩

绑定表头和业务行，识别数字单位、条件/否定与视觉来源；候选冲突形成打包组。最终压缩优先保持已标识关系，必要时减少辅助历史或整组移除证据。

这些是启发式关系保护，不保证所有语义关系被识别。`coverage_sufficient`、目标词命中仅为输入质量提示，不能证明问题可回答。

## 会话不是最近N轮全文

任务记忆显式启用后，按Owner和会话保存有限任务状态及相关历史。支持引用原句的状态修正/撤回，过滤假设更新；助手历史不作为技术证据。

模型还可获得近期对话，但其数量/长度有上限，提示预算不足时可进一步缩减。记忆与全部原始会话不等价。

## 可观察性

检查保留Evidence ID、原始与实际Token数、图片选择/去重、真实图片映射、目标缺失及保护组审计。UI找到的来源数量不等于实际进入模型的数量。

若Gold不在实际输入中，错误应先归检索/压缩/视觉选择；用Oracle正确证据再区分模型理解错误。最终收尾不会补回遗漏。
