# 简历与面试表述

## 简历项目描述

**建材销售与技术支持多模态RAG Agent｜Qwen3-VL、LangGraph、MinerU、FastAPI、Next.js**

- 面向产品资料、施工方案、节点图集和项目案例分散的问题，开发支持PDF、Word、Excel、施工图纸及图片输入的本地多模态知识助手。
- 设计保留页码、Sheet、单元格范围和图片区域的Canonical Evidence协议，构建BM25、向量召回及Cross-Encoder重排结合的图文RAG，实现原始节点图回传和可追溯引用。
- 基于LangGraph实现受约束Agent，自动路由客户附件、企业知识库、视觉理解和联网搜索；增加数值证据审计、证据不足拒答和多文件冲突提示。
- 使用Qwen3-VL-8B 4-bit本地推理，通过文本、像素、图片数量和生成长度预算适配16GB消费级GPU；客户附件使用会话级内存隔离，不写入企业知识库。

## 面试时应重点解释

1. 为什么不能把整份PDF直接交给模型：上下文、显存、可追溯性和错误归因都不可控。
2. 为什么表格要按行并绑定表头分块：防止字段名与数据值分离。
3. 为什么图片描述不能直接当事实：VLM标签只负责检索，工程结论仍需要正式文字证据。
4. 为什么Agent要受约束：模型负责计划，代码负责工具授权和隐私隔离。
5. 如何区分检索错误和模型错误：检查Gold Evidence是否真正进入Input Snapshot，并补充Oracle Evidence实验。

## 不应夸大的内容

- 未完成冻结测试前不要填写虚构准确率；
- 当前是小规模多文件问答，不是无限规模企业网盘检索；
- 当前支持主题总结，不承诺超长文档全文无遗漏摘要；
- 图片相似度只能生成候选，不能作为产品真伪认证。
