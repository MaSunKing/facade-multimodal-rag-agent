# 算法设计说明

本文说明项目中最主要的算法设计，以及每个模块为什么不能简单地替换成“把全部文件直接交给大模型”。

## 1. Canonical Evidence：保留格式差异的统一协议

不同格式共享统一的文档外壳，但不强行使用完全相同的位置字段：

```json
{
  "document_id": "doc_xxx",
  "file_name": "施工方案.pdf",
  "source_type": "pdf",
  "blocks": [],
  "tables": [],
  "visual_assets": [],
  "source_locations": []
}
```

格式专用位置包括：

| 格式 | 证据位置 |
|---|---|
| PDF | page、bbox、section |
| Excel | sheet、range、row、cell |
| Word | heading、paragraph、table |
| 图片 | visual_id、bbox、OCR候选 |

统一协议让检索器、训练数据和回答校验共享上层接口；专用位置则保证最终引用可以回到原始文件。

## 2. 结构感知分块

普通文本块过长时采用有限窗口和重叠切分，避免一句话正好被截断。表格不采用连续字符机械切分，而以完整数据行为候选，并绑定紧凑列头：

```text
[ROW]
A8[项目]='办公楼'
J8[安装方式]='锚固安装'
```

这样问题中的“安装方式”可以同时匹配字段和值，也避免重复整张表头导致索引词频污染。

完整 Evidence 永久保留；每道问题只生成独立 Input Snapshot。上下文预算不足不会删除原始解析内容。

## 3. PDF直接解析与视觉回退

PDF按页检查：

1. 文本层是否为空；
2. 是否存在大量乱码或自定义字体编码；
3. 文本顺序、字符密度是否异常；
4. 疑似表格能否恢复行列结构。

可靠文本页优先使用原生文本和表格解析。扫描页、乱码页及表格恢复失败页渲染为图片，交给OCR/版面分析或VLM。视觉结果首先是候选，未经可靠来源或人工确认不会成为正式技术事实。

## 4. 图文证据绑定

MinerU输出中的图片和表格截图被保存为独立视觉资产，记录：

- `asset_id`；
- 原始文档与页码；
- 裁剪区域 bbox；
- 图片标题、脚注和附近文字；
- 原始图片路径。

同页文字与图片通过页码、空间距离、标题和“见图”等指代表达计算关联分数。VLM生成的图片描述仅扩展检索词，技术结论仍需同页、可引用的文字证据支持。

## 5. 混合召回和重排

企业知识库的候选生成包含：

1. BM25词法召回：适合产品型号、规范编号和节点名称；
2. 可选本地向量召回：补充同义表达；
3. Cross-Encoder重排：根据完整问题与候选证据重新排序；
4. 领域和任务路由：节点图、施工流程、规范、案例使用不同优先级。

节点图检索还会过滤明显不匹配的命名节点，防止“用户问门窗节点，却返回普通参数表”。

客户临时附件采用透明、轻量的词法检索基线：先保证每份文件至少保留一个候选，再跨文件填充剩余预算。这样便于审计，也不额外占用16GB GPU。

## 6. 问题驱动的视觉选择

系统不会固定发送PDF首页或每份文件的第一张图。视觉资产排序综合：

- 问题词与OCR/标题/附近文字的重合；
- 已召回文本证据所在页或Sheet；
- 文件本身是否为直接上传的图片；
- 图片类型是否满足节点图、图表等任务要求。

受显存约束，单次只选择最相关的少量图片。模型是否看到Gold Evidence需要在输入快照中单独审计。

## 7. 受约束Agent而非自由Agent

语言模型生成工具计划，后端规则执行最终授权：

```text
问题理解
→ 候选工具计划
→ 规则校验与裁剪
→ 工具执行
→ 证据汇总
→ Grounded生成
→ 输出校验
```

这一设计避免模型自行拼接任意网络请求、读取未授权文件或跳过企业知识库直接依赖记忆回答。

## 8. Grounded输出协议

模型必须返回结构化JSON，并通过以下校验：

- 引用的Evidence ID必须真实存在；
- 关键结论必须有对应证据；
- 数值结论在证据文本中必须可验证；
- 来源冲突时不得静默选择其中一方；
- 没有足够证据时必须拒答。

验证完成后，后端将Evidence ID物化为用户可见的文件名、页码、Sheet、范围和原图链接。

## 9. 本地推理与资源预算

Qwen3-VL-8B使用4-bit NF4量化。资源控制包括：

- Batch Size = 1；
- 单题限制图片数、总像素、文本上下文和生成长度；
- 检索模型与生成模型顺序加载；
- 不保存hidden states、attention和生成分数；
- 空闲后释放生成模型显存。

这些设计使多模态RAG可以在消费级16GB GPU上运行，同时保留CPU词法检索降级路径。

## 10. 错误归因

端到端答错不一定等于模型能力不足。评测需要依次检查：

```text
原文件是否正确解析
→ Gold文件是否进入候选
→ Gold Evidence是否被召回
→ Gold图片是否进入模型输入
→ 模型是否正确理解
→ 输出是否通过引用校验
```

项目通过 Input Snapshot 保存实际进入模型的文本块和视觉资产，使解析错误、检索错误和模型错误可以分开统计。
