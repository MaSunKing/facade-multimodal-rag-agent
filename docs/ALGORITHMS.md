# 核心算法设计

## 1. Evidence-first

每条证据保留ID、内容、来源类型及位置；PDF用page/bbox，Excel用sheet/range，DOCX用段落/表格，图片用Visual Asset。格式统一的是上层协议，而不是强行把所有位置都变成页码。

模型只输出本轮允许的Evidence ID，后端从受控映射回填文件和位置。引用身份正确与引用内容支持结论不同，必须分别评测。

## 2. 结构感知候选

先按页面、段落、局部表格形成原生块，再按问题产生窗口。长文本窗口可配置，公开示例配置为768估计Token、96重叠；最终输入使用真实tokenizer复核。

表格按业务行绑定紧凑列头，如 `A8[Product]='DemoPanel-X' | B8[Thickness]=20`，不复制整个表头到每个单元格。合并区域、多张局部表与极宽行仍有启发式识别限制。

原始图独立保留，OCR/邻近文字仅提供检索线索。页面同时含文字和图片时，不应只保存OCR后丢弃像素信息。

## 3. 混合召回与候选保真

```text
BM25词法 + Qwen3-Embedding向量 → RRF → 候选保留 → Qwen3-Reranker
```

融合保留词法头部和Dense-only候选，避免单一路径挤掉另一条。向量索引须与词法索引指纹对应，访问范围在召回候选阶段过滤。

企业检索与客户附件检索不是同一实现：附件按问题检索业务行/窗口，可选语义重排；不将客户文件写入企业向量库。

16GB单卡上，生成模型已预留GPU时企业Dense/Reranker会被跳过，实际返回词法结果；其他索引/模型异常也有词法降级。可用混合链路不能宣传成每题必经链路。

## 4. Query-aware Context

不同来源的BM25、向量、SQL和视觉分数不可直接比较。先按来源内排名归一，结合Query匹配、结构和目标覆盖重排，再去重与打包。

保护关系包括表格行、数字/单位、条件/否定、视觉绑定和候选冲突组。处理的是已识别关系，不是完整语义无损压缩。保护组参与最终打包，不能只保留一个冲突值后声称无冲突。

冲突候选通过启发式指标/值/单位发现，主体、期间及业务口径尚未完全对齐；当前跨来源条件也可能漏掉同来源冲突。冲突应向用户说明并核对原文，而非自动认定哪方正确。

当前Fact normalization明确使用`entity + canonical metric + scope + version + normalized unit`构建事实键，并对显式数值做单位换算。只在相同事实键出现不同值时建立候选组，来源ID参与校验；不是把所有“厚度”值都归为冲突。历史原生TXT控制曾因解析wrapper导致5/5漏检；现已在匹配视图中只移除识别出的解析标记，保留原始Evidence，未知实体仍不强行绑定。统一原题回归原生冲突检测5/5，另测负冲突误报0/5；规模小且是已知开发题，不宣传为可靠通用冲突推理。完整口径见[统一评测](UNIFIED_EVALUATION.md)。

Planner同时输出`retrieval_queries`、`search_targets`、`answer_goals/answer_aspects`，检索消费来源语言目标，Context/目标重排围绕多个回答维度保留证据。检索字段长度、用户问题长度与最终模型Token预算分离，避免把语义要求裁成一个短检索字段。导航Evidence与回答Evidence分开，导航命中后可展开正文/业务行；这些机制不等于保证跨语言与多要求覆盖。

## 5. 图文联合输入

选择问题相关页/对象，经SHA去重、图片数量与像素预算后送入Qwen3-VL。实际输入序号由 `visual_input_manifest`绑定，不能使用检索列表位置猜图片序号。

企业图库按产品/案例/节点/工艺组织。指定产品采用审核名称/别名约束，未匹配不以相似图替代。图库图可能只返回展示，像素输入要单独核验。

图表有源单元格或明确标签时才有精确数值依据；仅凭柱高/折线视觉估读不能作为精确数据或检测结论。

## 6. 校验不是第二个大模型

生产校验主要用Python检查JSON结构、引用白名单、词汇/数字支持、部分宣传语和标准范围。数字出现在某条引用中，不证明主体/指标绑定正确；实际图片允许视觉观察，也不保证观察语义正确。

不能把接口成功、合法JSON、无OOM或校验通过直接写成答案准确率。

## 7. 资源与恢复

Planner尽量短结构化输出，必要时改写Query；GPU串行，检索/生成错峰。动态候选预算和真实提示预算分开，低负载不会扩大文件全文。

恢复由后端安全策略约束：最多两动作、每阶段一次、剩余时间达标、不延长deadline。不是每次失败都让LLM自由重规划，也不是可靠的语义自我修复。

恢复决策按目标、附件、企业RAG、视觉与授权网页证据的缺口选择有针对性的补充，不固定为扩大附件。规则仅约束权限、预算、错误类别及可恢复性，不用测试句子指定工具。公开CPU指标不覆盖Planner是否正确选择工具。

PDF/OCR可选调用通过`backend/stage_timing.py`记录细粒度耗时，解析与视觉资产按文档会话复用；最终只读预算内相关页。耗时审计用于定位瓶颈，不能直接推导固定P95或全题两分钟保证。
